# Configuración

## Versiones de OpenCode (v1 y v2)

`ywai` soporta tanto **OpenCode 1** (`opencode`) como **OpenCode 2** (`opencode2`), gestionando automáticamente las diferencias de formato y comportamiento:

| Característica | OpenCode v1 (`opencode`) | OpenCode 2 (`opencode2`) |
|---|---|---|
| **Binario** | `opencode` | `opencode2` |
| **MCPs** | Plano en `mcp.<id>` con `"enabled": true\|false` | Anidado en `mcp.servers.<id>` con `"disabled": true` |
| **Array de plugins** | `"plugin": [...]` | `"plugins": [...]` |
| **TUI / CLI config** | `~/.config/opencode/tui.json` (`"plugin"`) | `~/.config/opencode/cli.json` (`"plugins"`) |
| **Permisos de agentes** | Mapa YAML `permission:` | Lista ordenada de reglas `permissions:` |
| **Delegación** | `background-agents` plugin (`delegate` tool) | Soporte nativo de `subagent` |

### Cambiar de versión

Podés elegir qué versión conduce `ywai` de tres formas:

1. **Desde Settings UI**: En la pestaña **General**, selector *OpenCode version* (`Autodetect`, `v2 — opencode2`, `v1 — opencode`).
2. **Desde CLI**:
   ```bash
   ywai config set opencode_version v2   # o v1
   ywai config get opencode_version
   ```
3. **Variable de entorno temporal** (para CI o corridas puntuales):
   ```bash
   YWAI_OPENCODE=v1 ywai install
   ```

Por defecto, si no se especifica ninguna versión, `ywai` autodetecta prefiriendo OpenCode 2 (`opencode2`) si está en `$PATH`, o OpenCode v1 como fallback.

## Estructura

Ambas versiones comparten el directorio global `~/.config/opencode/`:

```
~/.config/opencode/
├── opencode.json     # agents JSON, MCP (mcp o mcp.servers según versión), default_agent
├── cli.json          # v2: tema, keybinds, plugins CLI (en v1: tui.json)
├── agents/           # Un .md plano por agente (lo instala ywai)
├── skills/           # Skills extra
└── commands/         # Slash commands
```

`ywai install` / `ywai update` **borra** de `agents/` cualquier `.md` que no pertenezca al grupo activo (core + qa-automation por defecto). Los custom van en el **proyecto**, no ahí.

## Perfiles de agentes (source)

En el repo / cache de ywai cada perfil tiene:

| Archivo | Qué contiene |
|---|---|
| `AGENT.md` | System prompt |
| `permissions.json` | Permisos (mapa interno; ywai lo exporta a reglas v2) |
| `skills.txt` | Allowlist de skills que ese agente puede cargar |

Instalado queda un solo archivo: `~/.config/opencode/agents/<nombre>.md` (frontmatter YAML + body).

## Personalizar

<Steps>

1. Editá el source (`ywai/agents/...` o el cache) o un agente de **proyecto**.
2. `AGENT.md` = comportamiento.
3. `permissions.json` = permisos. En el `.md` instalado se ven como `permissions:` (action / resource / effect).
4. `skills.txt` = IDs permitidos. OpenCode 2 anuncia solo esos; el body se carga con la tool `skill`.
5. `ywai update --agent opencode` y reiniciá OpenCode.

</Steps>

<Aside type="caution">
No dejes agentes custom solo en `~/.config/opencode/agents/`. El próximo install los prunea. Usá `.opencode/agents/<nombre>.md` en el repo.
</Aside>

## Configuración del proyecto

### AGENTS.md

```markdown
# AGENTS.md

## Convenciones
- TypeScript estricto
- Commits convencionales
- Tests con Vitest
```

OpenCode 2 descubre `AGENTS.md` hacia arriba desde el directorio de trabajo.

### Skills del proyecto

```
mi-proyecto/.opencode/skills/mi-skill/SKILL.md
```

o `.agents/skills/mi-skill/SKILL.md`. Reiniciá OpenCode. Para que un agente ywai pueda cargarlo, agregá el id a su `skills.txt`.

### MCP

En `opencode.json`, servers bajo `mcp.servers`. Para dejar uno apagado usá `"disabled": true` (`enabled` lo ignora v2).

## Verificar

ywai doctor
