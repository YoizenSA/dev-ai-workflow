# Testing Completo

El **orchestrator** coordina testing completo. Le decís qué testear y él distribuye el trabajo al equipo core.

## Testing simple

```
Escribe tests unitarios para el UserService.
Cubre: crear usuario, actualizar, eliminar, buscar por email.
```

El orchestrator:
1. Delega a `@qa` para escribir los tests
2. Te reporta los tests creados

## Testing con estrategia

```
Testea completamente el flujo de checkout.
Necesito: estrategia de testing, tests unitarios, de integración, y e2e.
```

El orchestrator:
1. Delega a `@qa` para diseñar la estrategia y escribir los tests
2. Delega a `@finder` para buscar código relacionado
3. Delega a `@reviewer` para revisar la calidad
4. Te reporta: "25 tests escritos, 92% cobertura, 0 tests frágiles"

## Con command

```
/qa-exploratory Testear completamente el flujo de checkout
```

El command lanza el ciclo exploratorio de QA automáticamente.

## Ejemplo real: Flujo de checkout

```
Tú: "Testea completamente el flujo de checkout.
     Debe cubrir: agregar al carrito, aplicar descuento, 
     seleccionar envío, pagar, y confirmar orden."

Orchestrator:
  → @qa: estrategia → unit para lógica, integration para API, e2e para UI
  → @finder: encuentra 15 archivos relacionados con checkout
  → @qa: escribe 25 tests cubriendo todos los flujos
  → @reviewer: encuentra 3 tests frágiles, sugiere fixes
  → Reporta: "25 tests, 92% cobertura, 0 tests frágiles."
```

## Ejemplo real: API completa

```
Tú: "Testea toda la API de usuarios.
     Endpoints: CRUD de usuarios, búsqueda, y autenticación."

Orchestrator:
  → @qa: priorizar autenticación > CRUD > búsqueda, tests para cada endpoint
  → @reviewer: revisa cobertura y calidad
  → Reporta: "40 tests, 88% cobertura."
```

## Tipos de tests

| Tipo | Cuándo usar | Framework |
|---|---|---|
| Unit | Lógica de negocio | Jest, Vitest, Go testing |
| Integration | API endpoints | Supertest, httpexpect |
| E2E | Flujos completos | Playwright |

<Aside type="tip">
Para tests de 1-2 funciones, decile al orchestrator que use `@qa` directamente. Usa `/qa-exploratory` cuando necesites una estrategia completa post-implementación.
</Aside>
