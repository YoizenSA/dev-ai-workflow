# QA Ask

El qa-ask responde preguntas de testing: explica frameworks, patrones y mejores prácticas con ejemplos. No escribe suites ni revisa código — para eso están `@qa-dev` y `@qa-reviewer`.

## Qué hace

1. **Explica frameworks** — Cómo testear X con tu stack (Vitest, Playwright…).
2. **Compara enfoques** — Unit vs integration vs e2e para tu caso concreto.
3. **Da ejemplos mínimos** — Mocks, fixtures, aserciones que muerden.
4. **Responde desde evidencia** — Si la pregunta es sobre tu repo, pide scout a `@finder` en vez de adivinar.

## Cuándo usarlo

| Tarea | Ejemplo |
|---|---|
| Cómo testear algo | `@qa-ask ¿Cómo mockeo API calls en Vitest?` |
| Frameworks | `@qa-ask ¿Unit o integration para este caso?` |
| Mejores prácticas | `@qa-ask ¿Cómo testeo error handling?` |

## Routing

| Tarea | Handler |
|---|---|
| Escribir la suite | `@qa-dev` |
| Revisar tests existentes | `@qa-reviewer` |
| Explorar el repo para responder | `@finder` |

## Límites

| ✅ Puede | ❌ No puede |
|---|---|
| Responder y ejemplificar | Escribir tests completos (`@qa-dev`) |
| Explicar frameworks y patrones | Revisar código (`@qa-reviewer`) |
| Guiar paso a paso | Ejecutar cambios en el repo |

<Aside type="tip">
Para aprender testing guiado en vez de una respuesta puntual, el grupo QA Automation tiene flujo con `@qa-orchestrator`.
</Aside>
