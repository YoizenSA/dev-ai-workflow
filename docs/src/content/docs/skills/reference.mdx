# Skills Reference

Las 29 skills que ywai instala, tal como viven en `ywai/skills/`. Cada una le da al agente conocimiento especializado que se carga por id (`skill`) sólo cuando el trigger aplica, así que no ocupan contexto mientras no hacen falta.

<Aside type="note">
El campo **Trigger** viene del `description:` de cada `SKILL.md`. Es lo que el modelo lee para decidir si carga la skill, no una lista de comandos que tengas que escribir.
</Aside>

## Frontend

### angular

**Trigger:** components, signals, inject, zoneless, forms, validation, lazy loading, file placement

Patrones de Angular: dónde va cada archivo, cuándo usar signals, formularios y validación, carga diferida.

### yz-ui

**Trigger:** componentes Yoizen UI, estilos, colores, tipografía, polish de frontend Angular

El design system de Yoizen: componentes, tokens de color, tipografía.

## Testing

### tdd

**Trigger:** desarrollo test-first, TDD

El loop de TDD sobre un vertical slice por vez: rojo → verde → refactor. Nunca refactorizar en rojo.

### testing-expert

**Trigger:** auditar calidad de tests

Inspecciona fuerza de las aserciones, huecos de cobertura, y tests que pasan mientras la feature está rota.

### playwright-e2e-testing

**Trigger:** escribir o arreglar tests de browser

Playwright E2E: locators, waiting, page objects, autenticación, red.

### condition-based-waiting

**Trigger:** tests flaky, `waitForTimeout`, race conditions

Esperar sobre condiciones, no sobre timeouts. El antídoto a los tests flaky.

## DevOps

### devops

**Trigger:** CI/CD, Azure Pipelines, Helm, Kubernetes

Azure Pipelines y Helm Umbrella charts.

### docker

**Trigger:** crear o auditar un Dockerfile, hallazgos de contenedor

Escribir y endurecer Dockerfiles para Node/.NET/Angular sobre AKS.

## Workflow

### git-commit

**Trigger:** escribir un commit, nombrar una branch, cortar un release

Conventional commits, branching, SemVer, changelog.

### resolving-merge-conflicts

**Trigger:** merge conflict, rebase conflict

Resolver conflictos activos de git merge o rebase. Entiende el contexto de cada cambio, preserva intenciones sin inventar comportamiento y ejecuta checks automatizados.

### delegate-opencode2

**Trigger:** delegar a opencode2, modelos `opencode-admin`

Delegar una tarea acotada al CLI local `opencode2` y después verificar lo que vuelve. La delegación no transfiere la verificación.

### bulk-read

**Trigger:** leer archivo grande, bulk read, resumir archivos

Delegar la lectura de archivos grandes al worker barato `opencode2` y leer solo el resumen. El contenido del archivo nunca entra a tu contexto.

### ado

**Trigger:** review/vote/comment de PRs, listar/crear/actualizar work items

Azure DevOps vía el CLI `ado`.

## Code Quality y Diseño

### codebase-design

**Trigger:** mejorar la interfaz de un módulo, ubicar un seam, hacer código más testeable

Vocabulario para diseñar módulos profundos y aplicar el principio *design-it-twice*.

### domain-modeling

**Trigger:** codebase terminology, AGENTS.md, ADRs

Construir y afinar activamente el modelo de dominio: desafiar términos, plantear escenarios de casos borde y documentar glosarios y ADRs tan pronto cristalizan.

### diagnosing-bugs

**Trigger:** diagnosticar, debuggear esto, algo roto / fallando / lento

El loop de diagnóstico para bugs difíciles y regresiones de performance.

### improve-codebase-architecture

**Trigger:** revisar/auditar arquitectura, buscar candidatos a refactor

Review guiado de arquitectura con reporte HTML.

## Discovery y Entrevistas (Grilling)

### grilling

**Trigger:** stress-test my thinking, grill

Entrevista implacable al usuario para poner a prueba un plan o decisión. Modela las decisiones como un árbol de diseño y avanza por rondas con preguntas y respuestas recomendadas.

### grill-with-docs

**Trigger:** `/grill-with-docs`

Entrevista implacable que además produce y actualiza los ADRs y el glosario de términos del modelo de dominio.

## Documentación

### adr-skill

**Trigger:** proponer/actualizar/aceptar/deprecar un ADR, inicializar la carpeta adr

Escribir y mantener Architecture Decision Records.

### diks

**Trigger:** documentar, runbook, incidente, postmortem

Documentar trabajo de infra como notas Zettelkasten en el repo de Infra.

### writing-great-skills

**Trigger:** escribir o editar una skill

Los principios que hacen que una skill sea predecible.

## Meta

### ywai

**Trigger:** ywai mcp, ywai profile, ywai groups, `/learn-ywai`, aprender ywai, cómo funciona ywai

Operar ywai (prender/apagar MCP, cambiar perfiles de modelo, habilitar grupos de agentes) y enseñarlo a partir de la documentación oficial, una página por turno.

### teach

**Trigger:** enseñame X

Enseñar una skill o concepto nuevo, dentro de este workspace.

### i-have-adhd

**Trigger:** `/i-have-adhd`

Formatea la salida para un lector con TDAH: próxima acción primero, pasos numerados, sin tangentes.

<Aside type="tip">
No hace falta memorizarlas. El modelo carga la skill por id cuando aplica; esta referencia es para ver qué hay.
</Aside>
