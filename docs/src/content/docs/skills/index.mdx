# Skills

## Qué son

Guías especializadas (`SKILL.md`). OpenCode 2 **anuncia** id + descripción; el body entra cuando el modelo llama la tool `skill`. `skills.txt` del agente es la allowlist.

## Dos capas

| Capa | Qué es | Ejemplo |
|---|---|---|
| **Base (gentle-ai)** | Skills del ecosistema que `ywai install` trae con `InstallEcosystem` | `typescript`, `playwright`, `react-19`, `dotnet`, `go-testing` |
| **Extra (ywai)** | 30 skills propias en `ywai/skills/` | `angular`, `yz-ui`, `tdd`, `ado` |

El `skills.txt` de cada agente mezcla ambas capas. Ver la [referencia completa de las extra →](/dev-ai-workflow/skills/reference).

```
Tú: "@dev Crea un componente Angular con yz-ui"
     ↓
OpenCode lista skills permitidos (id + descripción)
     ↓
El modelo llama skill("angular") / skill("yz-ui")
     ↓
Resultado: código que sigue esos patrones
```

## Crear un skill personalizado

1. Crear `mi-proyecto/.opencode/skills/mi-skill/SKILL.md`
2. Reiniciar OpenCode (`opencode2`)

El `skills.txt` no aplica en tu proyecto: es la allowlist de los perfiles de agente del **repo de ywai** (`ywai/agents/...`). OpenCode anuncia los skills del proyecto por sí solo. Los agentes sin allowlist (`ask`, `finder`, `orchestrator`...) lo cargan sin nada extra; los que tienen allowlist (p. ej. `dev`) solo ven lo de su lista, y para sumarles uno hay que editar su perfil en el repo de ywai.
