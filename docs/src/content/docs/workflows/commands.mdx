# Workflow Commands

## Qué son

Comandos slash que lanzan un flujo completo de agentes. Los escribís en opencode y el orchestrator coordina todo.

## Commands preinstalados

ywai trae 5 workflows semilla que se instalan como slash commands (más `/learn-ywai`, que es un command plano del host, no un workflow):

| Command | Flujo | Para qué |
|---|---|---|
| `/ship` | scout → plan → design → implement → test → review → deploy | Entrega completa end-to-end |
| `/planning` | scout → plan | Investigar y planificar antes de implementar |
| `/qa-automation` | analyst → finder → dev → reviewer | Testing completo |
| `/qa-exploratory` | summary → scenarios → verify → feedback | Testing exploratorio post-implementación |
| `/scenario-verification` | run scenarios → file evidence | Verificar BDD contra la app corriendo |
| `/learn-ywai` | Lee los docs oficiales (una página por turno) | Aprender ywai |

## Cómo usarlos

```
/ship Implementar autenticación con JWT
```

Esto lanza automáticamente:
1. `@finder` scoutea el alcance
2. `@planning` investiga y planifica
3. `@architect` diseña la solución
4. `@designer` define el spec si hay UI
5. `@dev` implementa
6. `@qa` testea
7. `@reviewer` revisa
8. `@devops` despliega si aplica

## Qué genera el export

Un workflow exportado son archivos reales que opencode lee:

| Elemento | Dónde queda |
|---|---|
| Slash command `/nombre` | `~/.config/opencode/commands/<nombre>.md` |
| Orchestrator (`<nombre>-orchestrator.md`, con el diagrama y los pasos) | `~/.config/opencode/agents/` |
| Un agent por nodo SubAgent (`<nombre>-<slug>.md`) | `~/.config/opencode/agents/` |
| Routing (`askUserQuestion` / `ifElse` / `switch`) | Dentro del prompt del orchestrator |

El diseño editable (JSON) vive en `~/.ywai/workflows/<nombre>.json`; lo generado se puede reconstruir siempre. Ojo: `ywai install`/`update` re-exporta los workflows instalados pero deja en `agents/` solo el grupo activo — un workflow exportado hay que volver a exportarlo, o guardarlo en `.opencode/agents/` del repo. Detalle de Studio: [Workflow Studio](/dev-ai-workflow/workflows/studio).

## Crear tus propios commands

### Con Studio (visual)

1. Abrir `http://localhost:5768/workflows`
2. Diseñar el flujo
3. Exportar como command

### Con JSON (avanzado)

```json
{
  "name": "mi-command",
  "nodes": [
    { "id": "start", "type": "start" },
    { "id": "dev", "type": "subAgent", "agent": "dev" },
    { "id": "qa", "type": "subAgent", "agent": "qa" },
    { "id": "end", "type": "end" }
  ],
  "edges": [
    { "source": "start", "target": "dev" },
    { "source": "dev", "target": "qa" },
    { "source": "qa", "target": "end" }
  ]
}
```

## Cuándo usar commands vs agentes

| Situación | Command | Agente directo |
|---|---|---|
| Entrega completa | `/ship` | |
| Plan antes de implementar | `/planning` | |
| Testing completo | `/qa-automation` | |
| Testing exploratorio | `/qa-exploratory` | |
| Verificar escenarios BDD | `/scenario-verification` | |
| Bug simple | | `@dev` |
| Pregunta rápida | | `@ask` |

<Aside type="tip">
Los commands son para flujos complejos. Para tareas simples, usá un agente directamente.
</Aside>
