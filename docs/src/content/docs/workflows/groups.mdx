# Agent Groups

## Qué son

Equipos predefinidos de agentes diseñados para trabajar juntos en tareas específicas.

## Los grupos

`ywai install` instala **core**. Los otros, si existieran via `groups.local.json`: `ywai groups enable <name>`. Disable quita esos `.md` (no core). El install también **prunea** leftovers (gentle, grupos apagados).

### Core

| Agente | Rol |
|---|---|
| `orchestrator` | Coordinador |
| `dev` | Implementa código |
| `qa` | Escribe tests |
| `reviewer` | Revisión de código |
| `devops` | Infraestructura |
| `ask` | Preguntas |
| `finder` | Búsqueda |
| `planning` | Planificación |
| `advisor` | Segundo revisor (no se invoca directo) |

Subagent-only, fuera del install por defecto (llegan con `--all-groups`): `scenario-runner` (verificación BDD post-review), `planner-scout` + `planner-draft` (exploración y redacción de `@planning`).

**Para qué:** Desarrollo general.

### QA Exploratory (sin grupo propio)

`exploratory-orchestrator`, `feature-summary`, `test-author`, `verification-orchestrator`, `qa-feedback`. Detalle: [QA Exploratory](/dev-ai-workflow/agents/qa-exploratory). **Para qué:** ciclo exploratorio post-implementación que termina en ADO. Se instalan con `ywai install --all-groups`.

## Delegación entre agentes

```
Core:
  orchestrator → [dev, qa, reviewer, devops, ask, finder, planning]
  (advisor observa, no recibe delegaciones)

QA Exploratory:
  exploratory-orchestrator → [feature-summary, test-author]
  verification-orchestrator → [scenario-runner, qa-feedback]
```

## Cuándo usar cada grupo

| Situación | Grupo |
|---|---|
| Feature nueva | Core |
| Bug fix | Core |
| Pantalla o UI | Core (`@dev`; el orchestrator planifica la spec) |
| Testing con estrategia | Core (`@qa` + `@finder` + `@reviewer`) |
| Testing exploratorio post-implementación | QA Exploratory (`/qa-exploratory`) |

<Aside type="tip">
El único grupo instalable es `core` (siempre). Lo demás vive en disco y llega con `ywai install --all-groups` o cuando su workflow semilla se exporta.
</Aside>
